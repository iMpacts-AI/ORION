## 1. Demonstration Philosophy

A great engineering demo does not pretend a project is finished when it is still in development. A great engineering demo shows:
1. **Working functionality** running cleanly in real-time.
2. **Clear architectural reasoning** explaining why decisions were made.
3. **Honest boundary awareness** naming what is complete, what is partial, and what comes next.

## 3. The 60-Second Version (Core Workflow)

### Goal:
Demonstrate the end-to-end loop: Natural Language Input → AI Planning → Autonomous Tool Execution → Response Synthesis → Native Speech.

### Script:
> *"Here is how ORION processes a natural language request. I’ll ask it to check the host system’s health and give me a summary. Watch the activity feed on the right:"*

### Action:
1. Type into Command Input: `"Check current CPU usage and system memory"` and press **Enter**.
2. **Show the HUD transitions**:
   * State transitions: `STANDBY` → `THINKING` → `EXECUTING` → `RESPONDING` → `SPEAKING`.
   * OpenRouter Llama 3.3 70B plans two tool calls: `system.get_cpu_usage` and `system.get_memory_usage`.
   * Tools execute in parallel via the DAG dependency runner.
   * Model synthesizes the final report.
   * Windows SAPI voice outputs: *"CPU usage is 18% average... Memory usage is 64% utilized..."*

### Script Follow-Up:
> *"The model didn't guess those numbers. It formulated a structured plan, ORION executed the low-level OS tools in parallel, fed the observation back to the model, and the model synthesized this response. And all API keys remain strictly quarantined in the Main process."*

## 4. The 3-Minute Version (Architecture & Safety)

### Goal:
Show multi-screen depth: Computer-Use screen, AI Provider Network, and the Emergency Stop failsafe.

### Sequence:

#### Minute 1: The Provider Network (`NETWORK` Screen)
1. Click **NETWORK** in top navigation.
2. **Explain the AI Fabric**:
   * Show status indicators across OpenRouter, Groq, Gemini, GitHub Models, and DeepSeek.
   * Point out the active strategy switcher (`SPEED_FIRST`, `BALANCED`, `QUALITY_FIRST`, `OFFLINE`).
   * Click **Run Live Diagnostics**: show the live API ping returning latency metrics.
   * **Key Point**: *"If OpenRouter throttles or returns a 429, ORION automatically shifts to Groq or Gemini without dropping the task."*

#### Minute 2: Computer-Use & Element Grounding (`COMPUTER` Screen)
1. Click **COMPUTER** in top navigation.
2. Click **Observe Desktop Screen**:
   * Show live capture: active foreground window title, cursor coordinates, and UI Automation element bounding boxes.
3. Show **Dry-Run Mode**:
   * Type: `"Open notepad and write hello world"`.
   * Enable **Dry-Run Mode** checkbox.
   * Click **Execute Command**: show the decomposed action plan generated by the AI without moving the actual physical mouse.
   * **Key Point**: *"We enforce a dry-run simulation mode so users can verify what the agent will do before it touches the operating system."*

#### Minute 3: Safety & Emergency Stop
1. Trigger a mock continuous task.
2. Press the red **EMERGENCY STOP** button.
3. Show immediate state change:
   * Status flips to `[ESTOPPED ACTIVE]`.
   * Process supervisor logs: `Terminating active process trees via taskkill`.
   * New execution requests are rejected until reset.
   * **Key Point**: *"In computer-use agents, safety cannot be a software promise. It must be an architectural gate."*

## 5. The 5-Minute Technical Version (Senior Engineer / Mentor)

### Goal:
Deep technical dive into the source tree, test suite, and engineering decisions.

### Sequence:

1. **Test Suite Verification (Terminal)**:
   * Open terminal, run `npm test`.
   * Show all 40 test suites passing 100% green in pure process isolation.
   * Explain ADR-007: *"We transpile TypeScript in-memory and run each suite in a clean Node process to eliminate state leakage."*
2. **Electron IPC Security (Code)**:
   * Open `src/main/preload.ts` and `src/main/index.ts`.
   * Show `contextIsolation: true`, `nodeIntegration: false`.
   * Show that `.env` is loaded strictly in Main, and zero API tokens are passed through IPC.
3. **The DAG Dependency Resolver (`ExecutionContext.ts`)**:
   * Show how plans are converted into directed acyclic graphs.
   * Independent read-only tools run via `Promise.all()`, while state-modifying actions run sequentially with dynamic parameter substitution (`${step.1.output.value}`).
4. **Win32 Native Input Driver (`InputControlService.ts`)**:
   * Show native Windows `user32.dll` P/Invoke mouse events and `Wscript.Shell` SendKeys.
5. **Workstation Hardware Context**:
   * Show `nvidia-smi` and system specs: 12th Gen i7-12850HX, 128 GB RAM, RTX A5500 16 GB VRAM.
   * Explain the 3-month roadmap to move from cloud API models to local 14B models on Ollama.

## 6. Offline Fallback Contingency Plan

If Wi-Fi drops or cloud APIs are blocked:

1. In the Command Input or Provider Screen, select **OFFLINE** strategy.
2. Send command: `"Get system telemetry"`.
3. ORION routes through `LocalHeuristicAIProvider`:
   * Identifies `SYSTEM` intent deterministically.
   * Dispatches `system.get_info`, `system.get_cpu_usage`.
   * Emits synthesized offline response.
4. **Explain to Mentor**: *"We designed an explicit offline rule router so that network failure degrades gracefully rather than crashing with unhandled promise rejections."*
